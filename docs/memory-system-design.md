# Jingent AI 记忆系统设计方案

> 状态：学术研究 / 后续迭代参考。本文档总结记忆系统的分层边界、后端技术架构与可深挖的研究方向。
> 落地优先级：先实现「全局画像 + 细节记忆」两层边界与去重，再逐步引入遗忘曲线、记忆巩固等高级能力。

---

## 一、两层记忆的权责边界（最容易踩坑）

| 维度 | 全局画像 | 细节记忆 |
|---|---|---|
| 写入者 | **用户主导写入** | **AI 自动抽取** |
| AI 权限 | 只读，不能自动新增/修改 | 可新增、可合并、可软删除 |
| 注入方式 | 每次对话**固定全量注入** system prompt | **语义召回**，只注入相关几条 |
| 优先级 | 最高 | 较低 |
| 适用内容 | 角色设定、核心人设、硬性约束（例："叫我学姐"） | 零散偏好、临时习惯、细碎互动细节 |
| 检索 | 不走向量召回 | 走向量召回 |
| 生命周期 | 长期稳定 | 允许重复、允许随时间遗忘 |

**核心原则：全局画像不走向量召回，固定注入；细节记忆走语义召回，控制 token 成本。**

---

## 二、后端完整技术架构（四大模块）

### 模块 1：抽取模块（最核心：怎么自动从对话里生成细节记忆）

**触发时机（异步，不阻塞流式回复）**

1. 会话结束触发
2. 每累计 20 轮对话触发一次（跟随后端输入最大轮数；必须走异步队列，不能在对话流里卡 LLM）

**抽取 Prompt 范式（Schema 输出，稳定可控）**

给 LLM 一段对话历史，指令（目前后端已实现，可参考添加）：

> 从对话里提取值得长期记住的事实、偏好、人设细节；过滤临时一次性内容；输出 json 数组；每条包含 content、tag；判断是否和已有记忆重复；动作：ADD / UPDATE / SKIP。
> tag 只能三选一：个人信息、喜好偏好、其他
> 禁止提取临时问答、单次任务结果、转瞬即逝的闲聊。

**时间维度**：对话数据都有时间，事件记忆最好结合时间一起存储，但不要刻意；AI 作为"人"应有遗忘曲线或记忆模糊，而非机械记录。

**去重合并逻辑**：用 embedding 算相似度，超过阈值（0.8~0.85）判定重复，自动合并或跳过新增，防止记忆爆炸。

---

### 模块 2：存储层

- 结构化元数据：id、content、tag、来源、时间、权重（以现有后端数据库字段为准）
- 向量检索：Chroma，给每一条细节记忆存 embedding
- 全局画像：直接存在用户主表，**不需要向量检索**，每次对话全量塞进 system prompt

> 区分：全局画像**不走向量召回，固定注入**；细节记忆走**语义召回**，只拉和当前用户 query 相关的几条，控制 token 成本。

---

### 模块 3：召回模块（每次对话之前执行）

流程：

1. 用户发消息 → 对用户 query 做 embedding
2. 在细节记忆向量库做 top-K 召回（一般取 3~6 条，不能太多）
3. 结合权重（importance、最近访问热度、时间衰减）重排
4. 把【全局画像 + 召回出来的相关细节记忆】拼进 system prompt 最前面，再丢给 LLM

> 重点：不要无脑把所有细节记忆塞 prompt，这是最常见错误——token 直接炸、幻觉暴涨。

---

### 模块 4：遗忘 & 维护机制（高级研究点）

模拟人类记忆衰减：

- 给每条细节记忆加半衰期衰减，长期没人召回、低重要度记忆慢慢降低权重，甚至软删除
- 记忆可视化：颜色表示熟悉度（深色=熟悉，浅色=陌生）
- 被多次召回的记忆权重升高、更不容易忘
- 经典方案：**Recency-Importance-Relevance 评分（源自 Generative Agents）**

## 三、可深挖的研究方向（从入门到前沿）

### 入门工程方向（适合 Jingent 落地）

1. 抽取 prompt 调优：减少无效记忆、减少幻觉记忆（AI 编造不存在的用户偏好）
2. 标签分类准确率优化：自动分类到「个人信息 / 喜好偏好 / 其他」
3. 召回策略对比：纯相似度 / 热度加权 / 时间衰减，哪个对话体验更好
4. 记忆冲突处理：新信息和旧记忆矛盾时，自动标记、让用户选择覆盖

### 进阶学术方向（论文路线）

1. **记忆巩固（Consolidation）**：碎片化细节记忆自动提炼，升级进入全局画像（自动把高频稳定偏好升级为核心画像）
2. **记忆图谱**：把记忆做成实体-关系图，而非一维列表（Neo4j），支持推理式回忆
3. **多会话隔离记忆**：项目里"主对话 = 宠物陪伴记忆，新建会话 = 普通 AI"这种**命名空间隔离记忆**是很好的特色研究点（LangGraph Memory Namespace / LangChain）
4. **记忆审计溯源**：每条记忆展示"是哪一轮对话提取出来的"，可溯源

### 实现要点（与文档的差异）

1. **向量存储不依赖 Chroma**：因 Chroma 依赖重、安装慢，细节记忆的 embedding 以 JSON 数组存 `memories.embedding` 列，召回时纯 Python 余弦相似度（1024 维 × 数十条，毫秒级），零额外依赖。
2. **embedding 服务**：本地 Ollama `bge-m3`（1024 维），与 `EMBEDDING_DIM=1024` 一致；首次加载约 20s，之后命中内存约 0.2s。
3. **抽取 Schema**：`EXTRACT_PROMPT` 已按文档改为 `tag` 三选一（个人信息/喜好偏好/其他）+ `action`（ADD/UPDATE/SKIP），SKIP 直接丢弃。
4. **触发阈值**：每累计 20 轮抽取一次（查该用户该角色最近 40 条 user/ai 消息，不足 20 轮跳过），抽取完整历史而非单轮。
5. **熟悉度可视化**：`memoryItemHTML` 根据 `access_count × 0.25 + (importance-0.5) × 0.6` 计算熟悉度，CSS 用 `--fam` 变量控制背景深浅。
